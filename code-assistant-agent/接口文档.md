# 接口文档

本文档整理 `code-assistant-agent` 项目当前已经实现的主要接口，覆盖 AI、Agent、工作台、认证四个模块。

适用场景：

- 前后端联调
- 接口测试
- 项目答辩演示
- 后续补充 Swagger / OpenAPI 前的手工文档版本

---

## 一、接口总览

当前接口按模块划分如下：

### 1. AI 模块

- `GET /api/ai/test`
- `POST /api/ai/chat`

### 2. Agent 模块

- `POST /api/agent/execute`
- `POST /api/agent/auto-execute`

### 3. 工作台模块

- `GET /api/workspace/dashboard`
- `POST /api/workspace/history`
- `GET /api/workspace/session-state`
- `POST /api/workspace/history/{id}/feedback`
- `POST /api/workspace/history/{id}/pin`

### 4. 认证模块

- `POST /api/auth/register`
- `POST /api/auth/login`
- `GET /api/auth/me`
- `POST /api/auth/profile`
- `POST /api/auth/change-password`
- `POST /api/auth/logout`

## 二、统一说明

### 1. 基础地址

本地开发环境通常为：

```text
http://localhost:8080
```

因此完整接口示例通常形如：

```text
http://localhost:8080/api/agent/auto-execute
```

### 2. 常用请求头

#### `Content-Type`

大多数 POST 接口使用：

```http
Content-Type: application/json
```

#### `Authorization`

登录态接口使用：

```http
Authorization: Bearer <token>
```

#### `X-Session-Id`

游客态 / 历史隔离相关接口常使用：

```http
X-Session-Id: session-xxx
```

说明：

- 游客模式下，系统通过 `sessionId` 隔离历史数据
- 登录模式下，后端主要按用户身份归属数据，但前端仍会携带 `X-Session-Id`

### 3. 返回格式说明

当前项目未对所有接口强制统一成同一种 envelope 格式，因此返回结果以“业务对象 JSON”为主。

异常时通常会由全局异常处理器返回错误信息，常见字段包括：

- `message`
- `status`
- `timestamp`

## 三、AI 模块接口

---

### 1. 测试 AI 连接

**接口地址**

`GET /api/ai/test`

**功能说明**

用于测试当前 AI 模型配置是否可用，验证：

- baseUrl
- apiKey
- model
- 网络可达性

**请求参数**

无。

**示例请求**

```bash
curl "http://localhost:8080/api/ai/test"
```

**示例响应**

```json
{
  "success": true,
  "model": "Qwen/Qwen3-235B-A22B-Instruct-2507",
  "message": "AI 服务连接成功",
  "replyPreview": "连接成功"
}
```

---

### 2. AI 通用聊天

**接口地址**

`POST /api/ai/chat`

**功能说明**

直接调用底层大模型进行聊天，不经过 Agent 编排。

适合：

- AI 服务联调
- 基础问答测试
- 验证模型响应效果

**请求体**

```json
{
  "message": "请解释一下 Java 中空指针异常为什么会出现",
  "systemPrompt": "你是一个面向编程初学者的助教"
}
```

**字段说明**

- `message`：用户输入内容，必填
- `systemPrompt`：系统提示词，可选

**示例请求**

```bash
curl -X POST "http://localhost:8080/api/ai/chat" \
  -H "Content-Type: application/json" \
  -d '{
    "message": "请解释一下 Java 中空指针异常为什么会出现",
    "systemPrompt": "你是一个面向编程初学者的助教"
  }'
```

**示例响应**

```json
{
  "model": "Qwen/Qwen3-235B-A22B-Instruct-2507",
  "content": "空指针异常通常表示你正在访问一个值为 null 的对象..."
}
```

## 四、Agent 模块接口

---

### 1. 结构化执行接口

**接口地址**

`POST /api/agent/execute`

**功能说明**

直接提交结构化任务，由 Agent 主流程执行。

适合：

- 前端结构化模式
- 后端联调
- 指定任务类型的精确测试

**请求头**

可选：

- `Authorization: Bearer <token>`
- `X-Session-Id: <sessionId>`

**请求体**

```json
{
  "taskType": "ERROR_EXPLANATION",
  "question": "请解释这个报错并给出修复建议",
  "code": "User user = null; System.out.println(user.getName());",
  "language": "Java",
  "errorMessage": "NullPointerException",
  "knowledgePoint": null,
  "practiceCount": null,
  "enableReflexion": true
}
```

**字段说明**

- `taskType`：任务类型，必填
- `question`：用户问题，必填
- `code`：代码片段，可选
- `language`：编程语言，可选
- `errorMessage`：报错信息，可选
- `knowledgePoint`：知识点，可选
- `practiceCount`：练习数量，可选
- `enableReflexion`：是否启用反思修正，可选

**示例响应说明**

返回内容通常包括：

- 最终回答
- 计划步骤
- 推理轨迹
- 工具调用轨迹
- 执行元信息

**示例响应结构**

```json
{
  "taskType": "ERROR_EXPLANATION",
  "answer": "这是一个空指针异常，原因是 user 为 null...",
  "planSteps": [],
  "reasoningSteps": [],
  "actionTraces": [],
  "toolTraces": [],
  "meta": {
    "usedReflexion": true
  }
}
```

---

### 2. 自然语言自动执行接口

**接口地址**

`POST /api/agent/auto-execute`

**功能说明**

用户只输入自然语言问题，系统会：

1. 自动解析任务类型和参数
2. 生成结构化请求
3. 调用 Agent 执行主流程

适合：

- 前端自然语言模式
- 真实用户使用场景

**请求头**

可选：

- `Authorization: Bearer <token>`
- `X-Session-Id: <sessionId>`

**请求体**

```json
{
  "message": "这段 Java 代码报空指针异常，帮我解释原因并告诉我怎么修复",
  "code": "User user = null; System.out.println(user.getName());",
  "enableReflexion": true
}
```

**字段说明**

- `message`：自然语言问题，必填
- `code`：代码片段，可选
- `enableReflexion`：是否启用反思修正，可选

**示例请求**

```bash
curl -X POST "http://localhost:8080/api/agent/auto-execute" \
  -H "Content-Type: application/json" \
  -H "X-Session-Id: session-demo-001" \
  -d '{
    "message": "这段 Java 代码报空指针异常，帮我解释原因并告诉我怎么修复",
    "code": "User user = null; System.out.println(user.getName());",
    "enableReflexion": true
  }'
```

**补充说明**

当前系统会自动尝试解析：

- `taskType`
- `question`
- `language`
- `errorMessage`
- `knowledgePoint`
- `practiceCount`

如果模型解析不稳定，还会辅以规则兜底。

## 五、工作台模块接口

---

### 1. 获取工作台概览

**接口地址**

`GET /api/workspace/dashboard`

**功能说明**

获取工作台首页展示所需的综合数据。

通常包括：

- 统计信息
- 快速提示词
- 最近历史

**请求参数**

无。

**示例请求**

```bash
curl "http://localhost:8080/api/workspace/dashboard"
```

**示例响应结构**

```json
{
  "stats": {
    "totalRequests": 18,
    "totalSessions": 6,
    "errorExplanationCount": 7,
    "algorithmGuideCount": 4
  },
  "quickPrompts": [
    "解释这个报错",
    "帮我讲解这个算法"
  ],
  "recentHistory": []
}
```

---

### 2. 获取历史记录

**接口地址**

`POST /api/workspace/history`

**功能说明**

按当前用户或当前 `sessionId` 查询历史记录。

**请求头**

可选：

- `Authorization: Bearer <token>`

**请求体**

```json
{
  "sessionId": "session-demo-001"
}
```

**字段说明**

- `sessionId`：当前会话标识，必填

**示例响应结构**

```json
[
  {
    "id": 1,
    "taskType": "ERROR_EXPLANATION",
    "userPrompt": "这段代码为什么会报空指针异常？",
    "responseSummary": "因为 user 为 null，访问其属性时触发异常",
    "answerContent": "详细解释内容...",
    "createdAt": "2026-04-19T10:20:30"
  }
]
```

---

### 3. 获取会话状态

**接口地址**

`GET /api/workspace/session-state`

**功能说明**

获取某个会话当前的状态信息。

**请求参数**

- `sessionId`：必填

**示例请求**

```bash
curl "http://localhost:8080/api/workspace/session-state?sessionId=session-demo-001"
```

**示例响应结构**

```json
{
  "sessionId": "session-demo-001",
  "messageCount": 4,
  "latestTaskType": "ERROR_EXPLANATION",
  "latestPrompt": "这段代码为什么会报空指针异常？",
  "hasPinnedRecord": false
}
```

---

### 4. 保存历史反馈

**接口地址**

`POST /api/workspace/history/{id}/feedback`

**功能说明**

给某条历史记录保存反馈。

**路径参数**

- `id`：历史记录 ID

**请求体**

```json
{
  "feedback": "helpful"
}
```

**说明**

可用于后续：

- 点赞 / 点踩
- 用户反馈收集
- 质量评估

**示例请求**

```bash
curl -X POST "http://localhost:8080/api/workspace/history/1/feedback" \
  -H "Content-Type: application/json" \
  -d '{"feedback": "helpful"}'
```

---

### 5. 置顶 / 取消置顶历史记录

**接口地址**

`POST /api/workspace/history/{id}/pin?pinned=true`

**功能说明**

切换某条历史记录是否置顶。

**路径参数**

- `id`：历史记录 ID

**查询参数**

- `pinned`：布尔值，表示是否置顶

**示例请求**

```bash
curl -X POST "http://localhost:8080/api/workspace/history/1/pin?pinned=true"
```

## 六、认证模块接口

---

### 1. 注册

**接口地址**

`POST /api/auth/register`

**功能说明**

创建账号并直接返回登录态。

**请求体**

```json
{
  "username": "testuser",
  "password": "123456",
  "nickname": "测试用户"
}
```

**字段说明**

- `username`：用户名，必填
- `password`：密码，必填
- `nickname`：昵称，必填

**示例响应**

```json
{
  "token": "xxxxxxxxxxxxxxxx",
  "user": {
    "id": 1,
    "username": "testuser",
    "nickname": "测试用户"
  }
}
```

---

### 2. 登录

**接口地址**

`POST /api/auth/login`

**功能说明**

用户登录并获取 token。

**请求体**

```json
{
  "username": "testuser",
  "password": "123456"
}
```

**示例响应**

```json
{
  "token": "xxxxxxxxxxxxxxxx",
  "user": {
    "id": 1,
    "username": "testuser",
    "nickname": "测试用户"
  }
}
```

---

### 3. 获取当前用户

**接口地址**

`GET /api/auth/me`

**功能说明**

根据 token 获取当前登录用户信息。

**请求头**

```http
Authorization: Bearer <token>
```

**示例响应**

```json
{
  "id": 1,
  "username": "testuser",
  "nickname": "测试用户"
}
```

---

### 4. 更新个人资料

**接口地址**

`POST /api/auth/profile`

**功能说明**

修改当前用户昵称。

**请求头**

```http
Authorization: Bearer <token>
```

**请求体**

```json
{
  "nickname": "新的昵称"
}
```

**示例响应**

```json
{
  "id": 1,
  "username": "testuser",
  "nickname": "新的昵称"
}
```

---

### 5. 修改密码

**接口地址**

`POST /api/auth/change-password`

**功能说明**

修改当前登录用户密码。

修改成功后，系统会清除当前用户已有登录会话，前端需要重新登录。

**请求头**

```http
Authorization: Bearer <token>
```

**请求体**

```json
{
  "oldPassword": "123456",
  "newPassword": "654321"
}
```

**成功响应**

无内容，返回 `200 OK`。

---

### 6. 登出

**接口地址**

`POST /api/auth/logout`

**功能说明**

删除当前 token 对应的登录态。

**请求头**

```http
Authorization: Bearer <token>
```

**成功响应**

无内容，返回 `200 OK`。
